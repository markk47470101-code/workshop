# Mark Desk

Свой десктопный интерфейс (Electron) для Claude Code CLI. Приложение не обращается к API
напрямую: каждое сообщение уходит в `claude -p --output-format stream-json`, а ответ
показывается по мере поступления — текст, размышления, вызовы инструментов и их результаты.

## Запуск

```powershell
npm install
npm start
```

`npm install` скачивает Electron. Если бинарник не загрузился (папка
`node_modules/electron/dist` пуста), выполните `node node_modules/electron/install.js`.

## Что умеет

- Потоковый вывод ответа с Markdown: заголовки, списки, таблицы, цитаты, блоки кода с кнопкой «Копировать».
- Карточки инструментов (Bash, Read, Edit и др.): раскрываются, показывают вход и результат.
- Своя история чатов: открыть, продолжить, удалить (кнопка × при наведении).
- Выбор рабочей папки, модели и режима разрешений.
- Остановка генерации (кнопка ■ или Esc), `Ctrl+N` — новый чат.
- Вход в аккаунт прямо из приложения (кнопка «Войти» запускает `claude auth login`).

## Своя история

История Mark Desk полностью независима: приложение не читает `~/.claude/projects` и не
показывает чаты Claude Code или десктопного приложения Claude.

```
%APPDATA%\Mark Desk\
  settings.json        настройки
  history\index.json   список чатов
  history\<id>.jsonl   события каждого чата
```

Файлы чатов приложение пишет само, поэтому история не пропадает, даже если CLI удалит свои
сессии. Для продолжения диалога используется `--resume` с id сессии CLI. Если сессия в CLI
исчезла, чат продолжится с чистого контекста — история на экране останется.

CLI при этом по-прежнему пишет собственные файлы сессий в `~/.claude/projects` и использует
общие вход и настройки. Чтобы отделить и это, включите в «Настройках» **«Отдельная конфигурация
CLI»**: тогда CLI получает `CLAUDE_CONFIG_DIR` внутри папки данных приложения — свой вход, свои
настройки, свои файлы сессий. После включения нужно войти заново, а глобальные настройки,
плагины и `CLAUDE.md` из `~/.claude` применяться не будут.

## Какой CLI используется

Порядок поиска: путь из настроек → `claude` в `PATH` → `~/.local/bin` и `%APPDATA%\npm` →
CLI, встроенный в десктопное приложение Claude. Путь можно задать вручную в «Настройках».

Для тестов путь можно переопределить переменной `MARK_DESK_CLAUDE_PATH`, а папку данных —
`MARK_DESK_USER_DATA`.

## Режимы разрешений

Приложение запускает CLI с `--permission-prompts none`: всё, что потребовало бы вопроса,
отклоняется, а не зависает. Поэтому режим выбирается заранее:

| Режим | Что происходит |
|-------|----------------|
| Принимать правки | файлы правятся без вопросов, прочие инструменты — только разрешённые |
| Только план | Claude читает и планирует, но ничего не меняет |
| Авто | решение принимает сам CLI |
| Всё разрешено ⚠ | никаких ограничений, включая команды оболочки |

Если Claude хотел что-то запрещённое, под ответом появится предупреждение.

## Проверка без аккаунта

В `test/` лежит поддельный CLI (`fake-claude.cmd`) и скрипт `drive.js`, который управляет
окном через DevTools и снимает скриншоты:

```powershell
$env:MARK_DESK_CLAUDE_PATH = (Resolve-Path test\fake-claude.cmd).Path
$env:MARK_DESK_USER_DATA = "$env:TEMP\mark-desk-test"
Start-Process node_modules\electron\dist\electron.exe -ArgumentList ".","--remote-debugging-port=9333"
node test\drive.js        # SCENARIO=chat | stop | nologin | history | reopen | missing | isolate
```

## Структура

```
main.js        процесс Electron: запуск CLI, история, вход, настройки
preload.js     безопасный мост (contextIsolation) между окном и main
src/           интерфейс: index.html, styles.css, app.js, markdown.js
test/          поддельный CLI и скрипт проверки интерфейса
```
