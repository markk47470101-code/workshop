# Mark Desk

Свой десктопный интерфейс (Electron) для Claude Code CLI. Приложение не обращается к API
напрямую: каждое сообщение уходит в `claude -p --output-format stream-json`, а ответ
показывается по мере поступления — текст, размышления, вызовы инструментов и их результаты.

## Запуск

```powershell
npm install
npm start
```

`npm install` скачивает Electron. Если бинарник не загрузился (папка
`node_modules/electron/dist` пуста), выполните `node node_modules/electron/install.js`.

## Что умеет

- Потоковый вывод ответа с Markdown: заголовки, списки, таблицы, цитаты, блоки кода с кнопкой «Копировать».
- Карточки инструментов (Bash, Read, Edit и др.): раскрываются, показывают вход и результат.
- Своя история чатов: открыть, продолжить, удалить (кнопка × при наведении).
- Выбор рабочей папки, модели и режима разрешений.
- Остановка генерации (кнопка ■ или Esc), `Ctrl+N` — новый чат.
- Вход в аккаунт прямо из приложения: кнопка «Войти» запускает `claude auth login`, ссылку можно
  открыть или скопировать, а код со страницы входа вставляется в поле и уходит в CLI.

## Своя история

История Mark Desk полностью независима: приложение не читает `~/.claude/projects` и не
показывает чаты Claude Code или десктопного приложения Claude.

```
%APPDATA%\Mark Desk\
  settings.json        настройки
  history\index.json   список чатов
  history\<id>.jsonl   события каждого чата
```

Файлы чатов приложение пишет само, поэтому история не пропадает, даже если CLI удалит свои
сессии. Для продолжения диалога используется `--resume` с id сессии CLI. Если сессия в CLI
исчезла, чат продолжится с чистого контекста — история на экране останется.

CLI при этом по-прежнему пишет собственные файлы сессий в `~/.claude/projects` и использует
общие вход и настройки. Чтобы отделить и это, включите в «Настройках» **«Отдельная конфигурация
CLI»**: тогда CLI получает `CLAUDE_CONFIG_DIR` внутри папки данных приложения — свой вход, свои
настройки, свои файлы сессий. После включения нужно войти заново, а глобальные настройки,
плагины и `CLAUDE.md` из `~/.claude` применяться не будут.

## MCP-серверы

Кнопка **«MCP-серверы»** в левом нижнем углу открывает управление серверами Model Context Protocol.
Серверы хранятся в `mcp.json` в папке данных приложения (там же лежат токены из переменных
окружения и заголовков) и при каждом запуске передаются CLI через `--mcp-config`.

- Добавить сервер можно формой (локальная команда `stdio`, удалённый `HTTP` или `SSE`) или вставкой JSON
  из документации сервера: `{ "mcpServers": { "name": { "command": "npx", "args": ["-y", "..."] } } }`.
- **«Проверить»** выполняет рукопожатие (`initialize` и `tools/list`) без обращения к модели и показывает
  список инструментов. Для SSE проверка недоступна, статус появится после первого сообщения.
- Переключатель у сервера включает и отключает его, не удаляя настройки.
- После запуска чата под полем ввода видно, сколько серверов подключилось («MCP: 2/3»), а проблемные
  серверы получают предупреждение в чате.
- На Windows команды без `.exe` (`npx`, `uvx`, `.cmd`) запускаются через `cmd /c` автоматически.
- Подтверждений в приложении пока нет, поэтому у сервера есть галочка «Разрешать Claude вызывать
  инструменты без подтверждения» (включена по умолчанию, в режиме «Только план» не применяется).
  Без неё вызовы инструментов сервера отклоняются.
- Галочка «Только серверы Mark Desk» добавляет `--strict-mcp-config`: CLI игнорирует MCP из своей конфигурации.

### Коннекторы аккаунта Claude (Higgsfield и другие)

Если CLI вошёл в аккаунт claude.ai, он сам подключает коннекторы этого аккаунта. В нижней части окна
«MCP-серверы» они показаны вместе со статусом (список берётся из `claude mcp list`). Галочка
**«Разрешить»** добавляет `--allowedTools mcp__<имя>`, и Claude вызывает инструменты коннектора без
подтверждения. Так подключён Higgsfield (`claude.ai Higgsfield`, инструменты `mcp__claude_ai_Higgsfield__*`).
В чате такие вызовы подписаны «Higgsfield · balance».

- Коннектор должен быть подключён на claude.ai (Settings → Connectors) — приложение этого не делает.
- В режиме «Только серверы Mark Desk» и при включённой «Отдельной конфигурации CLI» (другой вход) коннекторы
  недоступны.
- Higgsfield можно подключить и напрямую, не через аккаунт Claude: см. «OAuth для удалённых серверов».
  Если включены оба варианта, у Claude будет два набора одинаковых инструментов — лишний можно отключить.

### Разрешения по инструментам

Кнопка **«Разрешения»** у сервера открывает список его инструментов (приложение запрашивает его у сервера
и запоминает) с отметками «Claude может вызывать без подтверждения». Каждый инструмент помечен:
**чтение**, **изменяет** или **опасно**. Тип берётся из подсказок самого сервера (`readOnlyHint`,
`destructiveHint` из спецификации MCP), а если их нет — угадывается по названию (`list_`, `get_`, `ask_` —
чтение; `delete`, `decide`, `approve`, `pay`, `send` — опасно).

- Быстрые наборы: **«Только чтение»**, **«Без опасных»**, **«Все»**, **«Ни одного»**; дальше можно
  поправить отдельные галочки. «Обновить список» подтягивает инструменты заново.
- После сохранения разрешены только отмеченные инструменты (`--allowedTools mcp__сервер__инструмент`), а
  неотмеченные скрыты от Claude (`--disallowedTools`). **Новые инструменты, которые сервер добавит позже,
  по умолчанию недоступны** и помечены «новый», пока вы их не отметите.
- В режиме «Только план» разрешения не применяются, а запреты остаются.
- Если разрешения заданы по инструментам, в форме «Изменить» простые поля скрыты, а правка формой их не
  стирает.

### OAuth для удалённых серверов

У HTTP-сервера в форме можно выбрать «Авторизация → OAuth — вход через браузер». Кнопки
**«＋ Higgsfield»** и **«＋ 1Cifer»** добавляют готовые серверы с OAuth (`https://mcp.higgsfield.ai/mcp` и
`https://mcp.1cifer.kz/mcp`); затем нужно нажать **«Войти»** у сервера (вход сам не запускается).
У 1Cifer (рабочая система компании) инструменты разрешены целиком, **кроме** `decide` (решения по
карточкам согласования) и `delete_tasks` (удаление задач): они запрещены всегда, и решать за вас Claude не
сможет. Список можно поменять в «Изменить» → «Всегда запрещать эти инструменты».

Запрет (`--disallowedTools`) сильнее разрешения и действует в любом режиме; запрещённый инструмент
Claude просто не видит. Если сервер не разрешён вовсе («Разрешать Claude вызывать инструменты без
подтверждения» выключено), Claude получит отказ, а в чате появится подсказка, где это включить.

Как это работает (OAuth 2.1, как у Claude Code):

1. Приложение находит настройки сервера авторизации: ответ `401` с `WWW-Authenticate`, метаданные
   защищённого ресурса (RFC 9728) и сервера авторизации (RFC 8414).
2. Регистрирует себя на сервере автоматически (RFC 7591, клиент «Mark Desk»); регистрация запоминается.
   Если сервер так не умеет, в форме есть поле «OAuth Client ID».
3. Открывает браузер на странице входа (код авторизации + PKCE S256), ответ принимает на
   `http://127.0.0.1:53682/callback` (если порт занят — на свободном) и обменивает код на токены.
   Если сервер возвращает параметр `iss` (RFC 9207), он должен совпасть с сервером авторизации, а если
   сервер заявил о его поддержке — обязан прийти; иначе вход останавливается, а код не обменивается.
4. Токены хранятся зашифрованными средствами системы (`safeStorage`: DPAPI на Windows) в
   `mcp-oauth.json`, а не открытым текстом. Перед каждым запуском приложение обновляет истекающий
   токен само (refresh token).
5. В файл конфигурации для CLI токен не попадает: там `Authorization: Bearer ${MARK_DESK_TOKEN_…}`, а
   значение передаётся процессу CLI через переменную окружения.

«Выйти» стирает токены (регистрация клиента остаётся), удаление сервера стирает всё. Если сервер
отказал или вход отменён, причина показана в строке сервера.

## Какой CLI используется

Порядок поиска: путь из настроек → `claude` в `PATH` → `~/.local/bin` и `%APPDATA%\npm` →
CLI, встроенный в десктопное приложение Claude. Путь можно задать вручную в «Настройках».

Для тестов путь можно переопределить переменной `MARK_DESK_CLAUDE_PATH`, а папку данных —
`MARK_DESK_USER_DATA`.

## Режимы разрешений

Приложение запускает CLI с `--permission-prompts none`: всё, что потребовало бы вопроса,
отклоняется, а не зависает. Поэтому режим выбирается заранее:

| Режим | Что происходит |
|-------|----------------|
| Принимать правки | файлы правятся без вопросов, прочие инструменты — только разрешённые |
| Только план | Claude читает и планирует, но ничего не меняет |
| Авто | решение принимает сам CLI |
| Всё разрешено ⚠ | никаких ограничений, включая команды оболочки |

Если Claude хотел что-то запрещённое, под ответом появится предупреждение.

## Проверка без аккаунта

В `test/` лежит поддельный CLI (`fake-claude.cmd`) и скрипт `drive.js`, который управляет
окном через DevTools и снимает скриншоты:

```powershell
$env:MARK_DESK_CLAUDE_PATH = (Resolve-Path test\fake-claude.cmd).Path
$env:MARK_DESK_USER_DATA = "$env:TEMP\mark-desk-test"
Start-Process node_modules\electron\dist\electron.exe -ArgumentList ".","--remote-debugging-port=9333"
node test\drive.js        # SCENARIO=chat | stop | nologin | history | reopen | missing | isolate
```

## Структура

```
main.js        процесс Electron: запуск CLI, история, вход, настройки
mcp.js         MCP-серверы: хранилище, конфигурация для CLI, проверка соединения
oauth.js       OAuth 2.1 для удалённых MCP-серверов: обнаружение, вход, токены, обновление
preload.js     безопасный мост (contextIsolation) между окном и main
src/           интерфейс: index.html, styles.css, app.js, markdown.js
assets/        иконка приложения: icon.svg (исходник), icon.png, icon.ico
scripts/       make-icons.js — пересборка PNG и ICO из icon.svg (`npm run icons`)
test/          поддельный CLI и скрипт проверки интерфейса
```
